# 功能装备候选设计

状态：设计提案，尚未实现装备效果、安装、更换或界面。舰装配置目前预留一个 `equipmentSlot`，只表示槽位，不含已安装装备或运行逻辑。这里的例子是验证假设，不是已确定的游戏规则或数值。

## 目标和边界

功能装备应改变角色在狗斗中的情报、机动、协同或生存方式，让玩家能观察到选择的原因。炮、鱼雷等直接攻击武器属于 `weaponSlots`，不放入功能装备槽；舰娘人格仍决定如何使用已有能力。旧设计曾提出历史舰绑定固定舰装，而这里新增可安装功能槽；是否允许玩家更换、是否有舰种限制、如何与历史舰配置对应，都需要用户决定，不能擅自当作已确定。

## 候选装备

| 装备 | 候选作用与可观察反馈 | 对应玩法问题 | 前置机制 / 风险 |
| --- | --- | --- | --- |
| 雷达 / 索敌仪 | 增强特定范围内的探测或目标跟踪；显示扫描范围、发现与锁定变化 | 侦察型角色能否帮助全队更早行动？ | 现有共享情报是简化模型；范围、容量和衰减需要设计 |
| 火控仪 | 改善特定距离或锁定状态下的主炮火控；显示瞄准/散布变化 | 远程炮击能否选择稳定性而非最高火力？ | 不能变成无条件全方位加成；散布和命中公式需统一 |
| 航行控制器 | 改变转向响应或保持距离的能力；显示预计转弯轨迹 | 机动角色如何在弹幕和高楼间体现操控差异？ | 容易让角色无损躲避所有弹幕；需与人格、惯性分工 |
| 防空 / 近防系统 | 自动拦截满足条件的航空或导弹攻击；显示拦截线、冷却和覆盖范围 | 护卫舰能否保护友舰？ | 必须先有明确可拦截的攻击类别、容量、拦截顺序 |
| 反潜声呐 | 搜索水下目标或帮助跟踪；显示水下探测范围 | 潜航威胁能否驱动编队调整？ | 需要独立的水下探测、情报共享规则；不能直接创造攻击能力 |
| 电子干扰器 | 暂时干扰探测或锁定；显示干扰区与情报状态 | 掩护接近是否能形成不同路径？ | 需要情报衰减、干扰叠加和敌我对称规则 |
| 烟幕 / 遮蔽装置 | 在有限区域产生临时遮蔽；展示边界、剩余时间 | 能否制造移动掩护而不完全遮住弹幕？ | 需要定义只遮侦察还是也影响射击，避免视觉难读 |
| 应急维修装置 | 有限次数或间隔地恢复部分耐久；显示触发与恢复 | 持续战角色能否换取更长的上场时间？ | 可能造成无尽战斗；需要受限的次数、时机与数值 |
| 诱饵 / 假目标 | 释放短暂诱饵，影响部分目标选择或制导攻击 | 撤离和保护友舰是否有新的选择？ | 当前鱼雷不追踪，需先定义有效武器、判定和显示 |
| 侦察装置 / 无人机 | 临时扩展侦察覆盖或追踪数量；显示侦察单位/路径 | 是否值得牺牲战斗位获得更多信息？ | 需要单位生命周期、共享情报与拦截规则 |

## 建议的试验顺序

1. 先验证 **雷达**：与已有情报系统最接近，可比较首次发现、锁定时刻及战报可读性。
2. 再验证 **航行控制器**：用相同舰体和种子比较转弯、穿越弹幕及避障；注意它与角色人格的职责边界。
3. 最后选择 **近防** 或 **电子干扰**：前者先补拦截对象和容量，后者先补情报衰减。两项都需要新的规则，不应在这次直接实现。

评估每项装备时，比较同舰体、同武器、同 AI 的装与不装，记录可解释的动作变化、战斗时间、受损和对队友的影响。单槽意味着装备之间有机会成本，但是否应允许装配、卸下、更换或为各舰种固定，仍未定。
